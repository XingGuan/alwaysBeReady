# `MCP`  
`MCP`，全称是**模型上下文协议（`Model Context Protoccol`）**。  
你可以把它想象成`AI`领域的"`USB-C`接口"。在`MCP`出现之前，`AI`工具每连接一个新的数据源（`Figma`、蓝湖、数据库等），都需要开发一套单独的"适配器"，非常繁琐。`MCP`则提供了一个**统一的、开发的标准**，让`AI`应用可以通过这个"通用接口"，安全、双向地连接到各种外部工具和数据源。   

## `AI`是如何通过`MCP`"读懂"设计稿的？ 
这背后的原理就像使用一个"设计稿翻译官"，流程如下：  
1.`MCP`服务器（翻译官）：对于`Figma`和蓝湖，社区或官方开发了专门的"`MCP`服务器"。这个服务器知道如何与特定工具的`API`"对话"，并把复杂的设计数据"翻译"成`AI`能理解的结构化信息。   
2.**`AI`客户端（听众）**：像`Cursor`、`Claude Code`这类`AI`编程工具，它们本身就支持`MCP`协议。你只要在AI工具里配置好，告诉它去连接哪个"翻译官"（`MCP`服务器）即可。  
3.**标准化通信（共同语言）**：`MCP`协议规定了`AI`客户端和`MCP`服务器之间的"通信规则"。一旦连接，AI就能通过`MCP`服务器向`Figma`或蓝湖发出请求，获取数据。 
## `Figma`与蓝湖的"专属翻译官"有什么不同  
虽然原理相同，但这两个工具的`MCP`服务器在实现上略有差异：  
+ `Figma MCP`  
    + 来源：`Figma`官方已推出自己的`MCP`服务器，同时社区也有开源版本。  
    + 数据获取：主要通过`Figma API`来读取设计文件的结构化数据。  
    + 使用成本：官方版本通常需要Figma专业版及以上订阅。免费账号有调用次数限制。
+ 蓝湖`MCP`:
    + 来源：目前常见的方案多为**社区开发者维护的第三方开源项目**。  
    + 数据获取：通过模拟登录等方式，获取蓝湖平台内的设计稿结构化数据、预览图和切图资源。  
    + 使用成本：可免费使用，但通常需要使用时自行在本地进行部署和配置。  
## "读懂"之后,AI能做什么？  
一旦建立了连接，`AI`就能获得远超越一张截图的丰富信息，实现"设计稿转代码"。  
    + **读取结构化数据：** `AI`可以获取到精确的**"图层树、布局、颜色、字体、间距"**等信息。  
    + **提取设计变量**：能识别出你设计系统中定义的颜色、字体等变量（`Tokens`）,确保生成的代码与设计规范一致。  
    + **导出切图资源**：可以按照指令自动下载设计稿中标注好的图标、图片等切图资源。  
    生成更精准的代码：基于以上精准数据，`AI`能生成结构清晰、样式准确的前端代码（如`React、Vue`等），大幅提升开发效率。  

> `MCP`通过建立一个标准化的"通用语言",极大地简化了`AI`与外部世界的连接。而`Figma`和蓝湖的`MCP`服务器，正是在这个协议在具体设计工具之上的成功应用。
