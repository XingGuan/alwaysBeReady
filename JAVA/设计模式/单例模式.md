## 单例模式  
+ 核心考察点与常见填空  
> 私有静态实例、私有构造器、`getInstance()`方法。**懒汉式**的双重检查锁是高频考点，注意第一个判空不锁，第二个判空在锁内。  

### 一、单例模式的核心思想 
单例模式要解决三个问题：  
1.一个类只能有一个实例。 
2.这个实例必须由类自己创建。  
3.必须向整个系统提供这个实例的全局访问点。  

### 典型应用场景  
+ 配置管理器（读取配置文件）
+ 数据库连接池  
+ 日志对象  
+ 线程池  
+ `Spring`中的`Bean`默认就是单例  

考察的时候，题目中通常会给出一个类图，里面只有一个类，包含：  
+ 一个私有静态属性，类型是它自己。  
+ 一个私有构造方法。
+ 一个公有静态方法`getInstance()`,返回这个唯一实例。   

### 二、单例模式的标准结构 
不管哪种实现方式，都离不开这三个关键点：   
```java
    public class Singleton{
        // 1.私有静态实例，指向唯一的对象
        // private 变量只能在类的内部使用
        // static 标记变量属于类，只有一份
        private static Singleton instance;
        // 2.私有构造方法，防止外部 new
        // 私有构造方法，防止外部随便new出多个对象
        private Singleton(){}  
        //3.公有静态方法，返回唯一实例
        // 类名后面只能直接访问"属于类"的成员，也就是 static 成员  
        // 非静态成员属于对象，必须通过对象来访问
        public static Singleton getInsatnce(){
            // 创建或返回 instance
        }
    }
```
常考常挖空的位置就是：  
+ `private static Singleton instance;`中的**static** 和 **类型**。  
+ `private Singleton(){}`中的`private`  
+ `getInsatnce()`方法中的**static**  
+ 创建实例的语句`new Singleton()`  
+ 双重检查锁中的`synchronized`、两次`if(instance == null)`、`volatitle`关键字  

### 三、常见实现方式及代码分析  
1.饿汉式（`Eager Initialization`） 
```java
public class Singleton {
    // 类加载时就创建实例
    private static final Sigleton instance = new Singleton();  
    private Singleton(){}  
    public static Singleton getInstance(){
        return instance;
    }
}
```  
特点：  
+ 线程安全，因为类加载时只执行一次。  
+ 没有延迟加载，如果对象一直很大且一直没有用到，会浪费内存。 
+ `private static final Sigleton instance = new Singleton();`,基本就是饿汉式。  
填空点：  
+ `static final`修饰符  
+ `new Singleton()`  
+ `private`构造方法  

> `static final`修饰变量，这个变量属于类，并且只能赋值一次。  

2.懒汉式（线程不安全）  
```java
public class Singleton{
    private static Singleton instance;
    private Singleton(){}   
    public static Singleton getInstance(){
        if(instance == null){
            insatnce = new Singleton();
        }
        return instance;
    }
}
```  
特点：
+ 延迟加载，第一次调用才创建。  
+ 线程不安全：多线程同时进入`if`判断时，可能创建多个实例。

3.懒汉式（同步方法，线程安全但性能差）  
```java
public class Singleton {
    private static Singleton instance;  
    private Singleton(){}  
    public static synchronized Singleton getInstance(){
        if(instance == null){
            instance = new Singleton();
        }
        return instance;
    }
}
```
特点：线程安全，但每次调用都要加锁，性能差。 
`static synchronized`中`synchronized`是`Java`里的关键字，意思是：同步，用来控制多线程并发访问，保证同一时刻只有一个线程能执行某段代码。  
在你这段代码里：
```java
public static synchronized Singleton getInstance() {
    if (instance == null) {
        instance = new Singleton();
    }
    return instance;
}
```  
它的作用是：  
让`getInstance()`变成线程安全的同步方法，防止多线程同时创建多个`Singleton`实例。  
4.双重检查锁（`DCL,Double-Checked Locking`）  
它想解决什么问题？
> 单例要求：**整个程序只创建一个实例**，同时`getInstance()`可能被多线程同时调用。
如果直接这样：  
```java
public static synchronized Singleton getInstance(){
    if(instance == null){
        instance = new Singleton();
    }
    return instance;
}
```
能保证线程安全，但每次调用都加锁，性能较差。  
`DCL`的思路是：  
> 大多数情况下`instance`已经创建好了，直接返回即可，不必加锁；只有第一次创建时才加锁。  
2.第一次检查：避免每次都加锁  
```java
if(instance == null){
    synchronized(Singleton.class){
        ……
    }
}
```
当单例已经创建后，`instance != null`,线程直接返回，不会进入`synchronized`，性能好。  
3.第二次检查：防止重复创建  
假设没有第二次检查：  
```java
if(insatnce == null){
    synchronized (Singleton.class){
        instance = new Singleton(); // 没有第二次检查
    }
}
```  
两个线程 `A、B`同时调用：  
1.`A`和`B`都判断`insatnce == null`,都准备进入锁；
2.`A`先拿到锁，创建了实例，释放锁；
3.`B`再拿到锁，但它之前已经通过了第一次检查，如果没有第二次检查，它还会再创建一个实例。  
所以锁里面必须再检查一次：  
```java
if(instance == null){
    instance = new Singleton();
}
```  
这就是"双重检查"的含义：**锁外检查一次，锁内再检查一次**。  
4.为什么`instance`必须加`volatile`?  
因为`new Singleton()`不是原子操作，大致分三步：  
```java
1.分配内存空间  
2.初始化对象  
3.把引用`instance`指向内存空间  
```  
正常顺序是`1 -> 2 -> 3`。但如果没有`volatile`,`JVM`可能指令重排序成：  
```java
1. 分配内存空间
3. instance 指向内存空间
2. 初始化对象
```  
这时另一个线程可能看到：  
```java
if(insatnce == null) // 发现 instance 已经不是 null 
```  
于是直接返回`instance`，但这个对象可能**还没初始化完成**，拿到的是一个"半成品"。  
`volatile`在这里有两个作用：  
1.**禁止相关指令重排序**，保证对象初始化完成后才把引用赋给 `instance`；  
2.**保证可见性**，一个线程创建后，其他线程能及时看到。   

所以`DCL`里的`volatile`不是可有可无的，是正确性的关键。  
5.整体流程详解  
```java
public static Singleton getInstance() {
    if (instance == null) {                 // 大多数情况：已创建，直接跳过锁
        synchronized (Singleton.class) {    // 第一次创建时才加锁
            if (instance == null) {         // 防止多个线程排队后重复创建
                instance = new Singleton(); // volatile 防止半初始化对象被看到
            }
        }
    }
    return instance;
}
```
可以记成三句话：  
+ **第一次检查**：为了性能，避免每次加锁；  
+ **第二次检查**：为了正确性，防止多线程重复创建；  
+ `volatile`：为了防止指令重排序导致别的线程拿到未初始化完成的对象。  


完整代码
```java
public class Singleton {
    // volatile 防止指令重排序  
    private static volatile Singleton instance;
    private Singleton(){}  
    public static Singleton getInsatnce(){
        // 第一次检查，避免每次加锁
        if(instance == null){
            // 加锁
            synchronized(Singleton.class){
                // 第二次检查，防止多线程重复创建
                if(insatnce == null){
                    // 创建实例  
                    instance = new Singleton();
                }
            }
        }
        return instance;
    }
} 
```  
解释:  
+ `private static volatile Singleton instance`;  
    + `static`:属于类，全局唯一。
    + `volatile`：禁止指令重排序，保证多线程下的可见性和有序性。  
    + 为什么需要`volatile`?  
    `instance = new Singleton();`不是原子操作，分三步：  
    1.分配内存空间；
    2.初始化对象；
    3.将`instance`指向内存地址。  
    如果没有`volatile`,`JVM`可能重排序为`1->3->2`,导致其他线程拿到一个**未初始化完成**的对象。  
    `volatile`禁止这种重排序。
    + `if(instance == null)`
    第一次检查，如果实例已经存在，直接返回，避免进入同步块，提高性能。   
    + `synchronized(Singleton.class)`  
    对类对象加锁，保证同一时刻只有一个线程能进入创建代码。
    + `if(instance == null)` 
    第二次检查，防止多个线程同时通过第一次检查后，排队进入同步块时重复创建实例。 
    + `insatcne = new Singleton();`  
    创建唯一实例。  

    ### 考点  
    + `volatile`关键字  
    + `synchronized（Singleton.class）`
    + 两次`if(instance == null)`
    + `instance = new Singleton();`  

5.静态内部类（推荐，线程安全且延迟加载）  
```java
public class Singleton {
    // 私有构造方法，防止外部直接 new Singleton(),保证只能通过`getInstance()`获取实例
    private Singleton(){}  
    // 静态内部类，Holder 是 Singleton 的私有静态内部类，外部类 Singleton 加载时，内部类 Holder 不一定会被初始化，只有当代码第一次访问 Holder.INSTANCE 时，才会触发 Holder 类初始化
    private static class Holder{
        // 创建唯一实例
        private static final Singleton INSTANCE = new Singleton();
    }
    // 第一次调用 getInstance() 时，访问 Holder.INSTANCE，触发 Holder 初始化，创建实例。
    // 之后再次调用，Holder 已经初始化完成，直接返回同一个 INSTANCE。
    public static Singleton getInstance(){
        return Holder.INSTANCE;
    }
}
```  

特点：  
+ 外部类加载时不会初始化`Holder`，只有调用`getInstance()`时才加载内部类，实现延迟加载。  
+ 类加载机制保证线程安全。    

为什么线程安全？  
`Java`规定：一个类或接口的初始化过程，`JVM`会保证线程安全。  
也就是说，多个线程同时第一次访问`Holder.INSTANCE`时：  
+ 只有一个线程会真正执行`Holder`的类初始化；  
+ 其他线程会等待；  
+ 初始化完成后，所有线程拿到的是同一个`INSTANCE`。    

所以不需要自己写`synchronized`,也不需要`volatile`。
可以理解成：  
```java
private static final Singleton INSTANCE = new Singleton();
```  
这行代码在`Holder`类初始化时只执行一次，而`JVM`保证了类初始化只执行一次，并且是线程安装的。

可以这样理解：**用`JVM`的类初始化机制来保证线程安全，同时实现延迟加载。**  
+ 外部类加载，不创建实例；
+ 第一次调用 `getInstance()`，触发 `Holder` 初始化；  
+ `JVM` 保证 `Holder` 初始化线程安全；
+ `static final` 保证实例只赋值一次；
+ 后续调用直接返回同一个实例。


考点:  
+ `private static class Holder`  
+ `private static final Singleton INSTANCE = new Singleton();`  
+ `return Holder.INSTANCE;`  


6.枚举（最简洁，防反射和序列化破坏）  
```java
public enum Singleton{
    INSTANCE;
    public void doSomething(){
        // 业务方法
    }
}
```  
+ 天然线程安全，且能防止反射和反序列化创建新实例。

+ `《Effective Java》`推荐方式。  

这是**枚举单例（`Enum Singleton`）**,是`Java`中实现单例的一种写法，而且通常被认为是最简洁、最安全的单例实现之一。  
这里的`INSTANCE`不是普通字段，而是**枚举的唯一常量**,也就是单例对象本身。  
使用方式：  
```java
Singleton.INSTANCE.doSomething();
```  
它为什么是单例:  
`Java`规定：  
+ 枚举常量在枚举类初始化时创建；
+ 每个枚举常量全局唯一；
+ `JVM`保证枚举类初始化过程是线程安全的；  
+ 枚举常量不能被外部`new`出来。    

```java
Singleton.INSTANCE  
```  
可以理解为`JVM`帮你保证了：  
```java
public static final Singleton INSTANCE = new Singleton();
```  
但比普通静态常量更安全。  
2.它天然防反射破坏  

总结  
```java   
public enum Singleton{
    INSTANCE;
}
```  
这是枚举单例： 
> 用一个枚举常量`INSTANCE`表示唯一实例，利用`JVM`对枚举类初始化的线程安全保证、枚举常量的唯一性、以及枚举对反射和反序列化的特殊保护，来实现最简单、最安全的单例。   
调用时用:  
```java
Singleton.INSTANCE.doSomething();
```
