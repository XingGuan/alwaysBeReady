`EG:`"区间打印格式"  
> 策略模式本质上就是一句话：把会变化的算法封装成独立的类，让上下文在运行时可以灵活替换它们。  

> 策略模式核心考察点与常见填空  
> 定义策略接口、具体策略类、上下文类(`Context`)中持有策略接口并调用其方法。

上下文不继承具体算法，而是"持有策略接口",把算法调用委托给接口；运行时替换，就是换掉它持有的那个接口引用。  

1.三个角色 
+ 策略接口：统一算法签名，保证可替换。  
保证可替换：接口引用可以指向任何实现类对象   
接口是一种**引用类型**。你可以声明一个接口类型的变量：  
```java  
DiscountStrategy strategy;
```  
这个变量可以指向任何实现了`DiscountStrategy`的对象：  
```java  
strategy = new VipDiscount();
strategy = new HolidayDiscount();  
strategy = new NoDiscount();
```  
编译器只关心`strategy`是`DiscountStrategy`类型，所以只允许你调用接口里声明的方法：  
```java  
strategy.discount(100);//合法
```  
但运行时，`JVM`会根据`strategy`实际指向的对象，去调用哪个对象自己的`discount`方法。这就是**动态绑定**（也叫运行时多态）。  
```java
DiscountStrategy strategy = new VipDiscount();
System.out.printIn(strategy.discount(100)); // 调用 VipDiscount.discount;输出 80  
strategy = new HolidayDiscount();  
System.out.printIn(strategy.discount(100));//调用 HolidayDiscount.discount; 输出 70  
```  
同一行调用代码`strategy.discount(100)`,因为`strategy`指向的对象变了，执行的方法就变了。**替换的是接口引用背后的具体对象，而不是接口本身。**  
3.上下文为什么能灵活替换？  
上下文（`Context`）不直接依赖`VipDiscount`、`HolidayDiscount`这些具体类，它只依赖接口：  
```java
class PriceContext{
    private DiscountStrategy strategy;
    public void setStrategy(DiscountStrategy strategy){
        this.strategy = strategy;
    }
    public double finalPrice(double price){
        return strategy.discount(price);
    }
}
``` 
`PriceContext`里的`strategy`是接口类型。你给它传`VipDiscount`,它就调`VIP`算法；传`HolidayDiscount`,它就调节日算法。上下文完全不知道具体是哪个类，也不需要改代码。  
这就是可替换性的来源：  
  + **编译期**：上下文只看到`DiscountStrategy`接口，只要求有`discount(double)`方法。
  + **运行期**：实际执行哪个`dicount`,由`strategy`指向的对象决定。
  + **替换方式**：调用`setStrategy(new XxxDiccont())`,改变接口引用指向的对象。  
  总结:
  + **统一签名**：接口声明`double discount(double price)`,所有实现类必须实现一模一样的方法。  
  + **可替换**：接口引用可以指向任何实现类对象，上下文持有接口引用，通过`setStrategy`换对象。  
  + **运行时决定**：`JVM`根据实际对象类型动态调用对应方法。  
  + **解耦**：上下文只依赖接口，不依赖具体算法类。

`interface DiscountStrategy`本身不实现算法，它只是定义了一个"算法插槽"。具体策略类是这个插槽的可插拔模块，多态让插槽在运行时可以换成不同模块。

+ 具体策略类：每个类封装一种算法。  
+ 上下文`Context`：持有策略接口，提供业务方法，内部调用策略。  
```java
// 策略接口  
interface DiscountStrategy{
    double discount(double price);
}
// 具体策略  
class NoDiscount implements DiscountStrategy{
    public double discount(double price){ return price; }
}
class VipDiscount implements DiscountStrategy{
    public double discount(double price){ return price * 0.8; }
}
class HolidayDiscount implements DiscountStrategy{
    public double discount(double price){ return price * 0.7; }
}
```  
2.**上下文怎么用策略**？  
上下文通过组合持有接口，然后委托调用：  
```java  
class PriceContext {
    private DiscountStrategy strategy;  
    //构造时注入
    public PriceContext(DiscountStrategy strategy){
        this.strategy = strategy;
    }
    //运行时替换  
    public void setStrategy(DiscountStrategy strategy){
        this.strategy = strategy;
    }
    public double finalPrice(double price){
        return strategy.discount(price); // 委托给策略
    }
}
```  
这里`PriceContext`不知道具体是`VipDiscount`还是`HolidayDiscount`,它只知道`DiscountStrategy`接口。  

3.客户端怎么调用？  
```java
PriceContext context = new PriceContext(new NoDiscount());
System.out.println(context.finalPrice(100)); // 100

context.setStrategy(new VipDiscount());
System.out.println(context.finalPrice(100)); // 80

context.setStrategy(new HolidayDiscount());
System.out.println(context.finalPrice(100)); // 70
```  
这就是运行时替换：  
**调用`setStrategy`改变上下文内部的接口引用，下一次`finalPrice`就会走新的算法。**  

4.运行时根据条件选择策略  
实际业务通常不会写死，而是根据用户、时间、配置等选择：  
```java
DiscountStrategy strategy;

if (user.isVip()) {
    strategy = new VipDiscount();
} else if (isHoliday) {
    strategy = new HolidayDiscount();
} else {
    strategy = new NoDiscount();
}

context.setStrategy(strategy);
double price = context.finalPrice(100);
```  
也可以选择逻辑封装到工厂：  
```java
context.setStrategy(DiscountStrategyFactory.get(user,date));
```  
这样客户端只负责"选策略"，上下文只负责"用策略"。
5.为什么能灵活替换？  
因为`Java`多态：  
```java
DiscountStrategy strategy = new VipDiscount();  
strategy.discount(100);// 调 VipDicount  
strategy = new HolidayDiscount();
strategy.discount(100); //调 HolidayDiscount
```  
上下文持有的只是接口引用，引用指向不同实现对象，调用时自然执行不同算法。  
6.注意事项  
  + 策略接口要稳定，所有具体策略实现同一方法签名。每个具体策略类，都必须实现策略接口里定义的那个一模一样的方法。  
  + 上下文不要自己`new`具体策略，否则又耦合了。  
  ```java
    class PriceContext {
        private DiscountStrategy strategy = new VipDiscount(); // 问题在这里

        public double finalPrice(double price) {
            return strategy.discount(price);
        }
    }
  ```  
  + 如果上下文是多线程共享的，`setStrategy`会影响所有线程；最好每次请求创建 `Context`,或把策略作为方法参数传入。
  + 策略通常无状态，可以复用单例。
  + 新增算法时，只增加一个具体策略类，不改上下文，符合开闭原则。
